# Current limitations

- The Groth16 setup uses a small, local, single-party Powers of Tau and one circuit-specific contribution. It is suitable for a reproducible classroom demonstration, not a production trusted setup.
- The local Circom compiler is downloaded from the pinned official 2.2.3 release and checked against its published SHA-256 digest. The compiler binary and ceremony intermediates are not committed. The circuit, final proving key, browser witness WASM, verification key, and artifact manifest are committed so teammates use the same proof parameters.
- The setup script downloads official Circom 2.2.3 binaries for x64 Windows, Linux, and macOS. Other architectures currently need a manually installed compiler of the same version.
- Local issuer keys and the app-to-issuer token live in ignored `.local/` files. If both services run under the same operating-system account, that directory layout does not isolate the private key from the app process; separate service identities and managed secrets would be needed outside this laptop demo.
- The mock issuer attests a calendar-valid birth date, but calendar validation is outside the circuit. The circuit proves the committed YYYYMMDD integer is at or before the server's stored challenge-day cutoff. The verifier must check the Ed25519 issuer signature, current credential status, stored cutoff, session and credential binding, and challenge hash before accepting a proof. Those HTTP workflows are not implemented yet.
- A public opaque credential ID and commitment may permit linkability across verification attempts. Neither the commitment nor signature belongs in user-facing results or exports.
