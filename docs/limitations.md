# Current limitations

- The Groth16 setup uses a small, local, single-party Powers of Tau and one circuit-specific contribution (`npm run zk:setup`). It is suitable for a reproducible classroom demonstration, not a production trusted setup (a compromised single-party ceremony could allow forged proofs if toxic waste were retained).
- The local Circom compiler is downloaded from the pinned official 2.2.3 release and checked against its published SHA-256 digest. The compiler binary and ceremony intermediates are not committed. The circuit, final proving key, browser witness WASM, verification key, and artifact manifest are committed so teammates use the same proof parameters.
- The setup script downloads official Circom 2.2.3 binaries for x64 Windows, Linux, and macOS. Other architectures currently need a manually installed compiler of the same version.
- Local issuer keys and the app-to-issuer token live in ignored `.local/` files. If both services run under the same operating-system account, that directory layout does not isolate the private key from the app process; separate service identities and managed secrets would be needed outside this laptop demo.
- The mock issuer attests a calendar-valid birth date, but calendar validation is outside the circuit. The circuit proves the committed YYYYMMDD integer is at or before the server's stored challenge-day cutoff. The verifier must check the Ed25519 issuer signature, current credential status, stored cutoff, session and credential binding, and challenge hash before accepting a proof. Both the HTTP verifier (`POST /api/verifications`) and the operator browser proof workflow (`src/app/public/prover-client.mjs`) are implemented; full dashboard/reporting screens remain under Member C.
- A public opaque credential ID and commitment may permit linkability across verification attempts. Neither the commitment nor signature belongs in user-facing results or exports.
- The circuit and its artifacts are named `age18`, but the circuit only proves the birth date is at or before the public cutoff. The admin-configured minimum age (13–25) changes the cutoff the server computes, so no new proving key is needed. A credential's commitment does not depend on the rule.
- Local benchmark timings in [performance.md](performance.md) reflect single-laptop Node.js `groth16.fullProve` (`singleThread: true`) and `verifyAgeProof` microbenchmarks; browser first-run latency also includes WASM/zkey download and WebAssembly initialization.
