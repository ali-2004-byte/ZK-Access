# Local account and bootstrap contract

The app and issuer use separate SQLite database files through Node.js built-in `node:sqlite`: ignored `.local/app/app.sqlite` and `.local/issuer/issuer.sqlite`. `src/db/account-store.mjs` creates their account tables with separate role checks and a unique normalized-username constraint. A local setup command will prompt for an app-admin username/password and a different issuer-admin username/password. Each password has at least 12 characters. The two services keep their accounts separate; each admin creates users only in their own service.

Usernames are trimmed, normalized with Unicode NFKC, then lowercased. Login lookup and uniqueness use only that normalized value. The normalized form must contain 3–32 ASCII letters or digits, dot, dash, or underscore (`[a-z0-9._-]`); length is counted after normalization, when all allowed characters are single-byte ASCII. The database enforces uniqueness on that form, and the initial app-admin and issuer-admin normalized names must differ.

Password storage uses asynchronous Node.js scrypt with a unique 16-byte random salt per password, N=131072 (2^17), r=8, p=1, a 64-byte derived key, and a 256 MiB memory limit. A stored string has the form `scrypt$N$r$p$salt$hash`, where salt and hash are unpadded canonical base64url. Verification accepts only power-of-two N from 16384 through 131072, exactly r=8 and p=1, and exact 16-byte salt and 64-byte hash lengths. It refuses out-of-range stored parameters before invoking scrypt and compares hashes with `crypto.timingSafeEqual`. The exact password text is not normalized.

Wrong username and wrong password return the same generic login error. An unknown username still triggers verification against a fixed dummy scrypt record. Login failures are limited per IP and normalized username: five failures in 15 minutes trigger a one-minute lockout. Attempts during an active lockout are rejected without incrementing the count or extending the deadline. After expiry, each new failed attempt doubles the delay up to 15 minutes. Successful login clears the failure state for that username and IP. Counters and deadlines persist in SQLite across restarts. Every failure and lockout is audit-logged, with unknown usernames redacted or hashed.

`npm run local:accounts` prompts in an interactive terminal for the missing app and issuer admin usernames and passwords, masks password entry, and asks for confirmation. It preserves existing admins on rerun and rejects equal normalized admin names. The command never prints or commits passwords, salts, hashes, signing keys, or service tokens. The account tables, hashing, bootstrap command, and persisted lockout helper are implemented. Login routes, dummy work, and failure audit remain to be integrated.
